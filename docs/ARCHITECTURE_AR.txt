----------------------------------------------------------------
1) الغرض من البرنامج
----------------------------------------------------------------
LarvIDE بيئة تطوير متكاملة (IDE) حقيقية تعمل على هواتف أندرويد،
صُممت أساساً لطلبة الجامعات في غزة الذين لا يملكون حواسيب محمولة
ويحتاجون لتنفيذ واجباتهم في Java وهياكل البيانات والخوارزميات
ولغات أخرى باستخدام الهاتف فقط.

مبادئ التصميم:
- يعمل دون اتصال بالإنترنت (Offline-first) بعد الإعداد الأولي.
- خفيف ومناسب للأجهزة الضعيفة (يدعم أندرويد API 21 فأعلى).
- لا يفتح أي تطبيق خارجي أثناء التشغيل — كل شيء داخل LarvIDE.
- مجاني للدراسة والاستخدام الشخصي، مع حماية حق المطور بالنسب.

----------------------------------------------------------------
2) نظرة عامة على البنية
----------------------------------------------------------------
التطبيق مبني بلغة Java (توافق Java 17) ويعمل بنمط Single-Activity:

  MainActivity (الواجهة والقائد الوحيد)
  ├── EditorFragment (محرر Monaco داخل WebView + جسر JS)
  ├── اللوحة السفلية: Problems / Preview / Terminal (ViewPager2)
  ├── شجرة المشروع: ProjectManager + ProjectRecognizer + FileTreeAdapter
  ├── RunDispatcher (موجّه التشغيل: لغة ← محرك)
  ├── ExecutionBackend (واجهة التنفيذ)
  │     ├── EmbeddedLinuxBackend (بيئة لينكس داخل التطبيق) [الأساسي]
  │     └── TermuxCommandBackend (تطبيق Termux الخارجي) [قديم/معطّل]
  ├── Dexer (مكتبة D8 لتحويل class إلى dex) + JavaRunner (تشغيل على ART)
  ├── SessionManager (حفظ الجلسات في .larv/session.json لكل مشروع)
  ├── ProjectIndexer + MemberCatalog (إكمال خفيف بالتعابير النمطية)
  └── مساحة عمل مشتركة: /sdcard/LarvIDE/projects

----------------------------------------------------------------
3) المكونات بالتفصيل
----------------------------------------------------------------
3-1) واجهة المستخدم (MainActivity)
- النشاط الوحيد في التطبيق: يدير شريط الأدوات، نافذة المشروع اليسرى،
  تبويبات المحرر، اللوحة السفلية، وشريط الحالة.
- يستقبل الأحداث من كل الأجزاء (فتح/إغلاق المشاريع، الحفظ، التشغيل)
  ويوزع العمل على خيوط خلفية، مع إرجاع تحديثات الواجهة لخيط UI.

3-2) المحرر (EditorFragment + editor.html)
- محرر Monaco (محرك محرر VS Code) يعمل داخل WebView من ملف محلي.
- يدعم لغات: Java و Python و JavaScript و HTML و CSS و JSON و XML و Markdown
  مع 5 ثيمات وخطوط برمجية وإعدادات (حجم الخط، الالتفاف، الأرقام...).
- جسر LarvIDE بين JS وجافا:
  - onContentChange: يرسل التعديلات (بتأخير 300ms لتقليل الضغط).
  - window.flushContent: دفع فوري للتعديلات قبل التشغيل حتى لا يُترجم كود قديم.
  - onCursorChange / طلب الإكمالات / عرض الأخطاء (squiggles).

3-3) نظام المشاريع
- ProjectManager: إنشاء/فتح/حذف/إعادة تسمية المشاريع والملفات والمجلدات،
  وقوالب جاهزة (.java / .py / .js / .html / .css / .json).
- ProjectRecognizer: يكتشف لغة المشروع تلقائياً (عمق ≤ 6، حد 400 ملف).
- المشاريع في تخزين مشترك /sdcard/LarvIDE/projects لتصل إليه كل الأجزاء.
- ملاحظة: لا يُنشأ ملف larvbuild.json تلقائياً؛ التشغيل يكتشف اللغة
  والملف من التبويب النشط، ومن يحتاج وسائط/إدخال يضيف الملف يدوياً.

3-4) نظام التشغيل (RunDispatcher)
- نقطة توجيه واحدة: تحدد اللغة (من الإعدادات ثم التبويب النشط ثم الكشف)
  وتختار المحرك المناسب:
  - Java: مترجم javac داخل بيئة لينكس ← ملفات class في .larv-classes
          ← مكتبة D8 تحولها إلى dex ← تشغيل على ART عبر JavaRunner.
          (مكتبة R8/D8 هي المكوّن المدمج الوحيد المحتفَظ به لأن ART
          لا يعمل إلا بصيغة dex ولا يوجد dexer في حزم لينكس).
  - C/C++‎: clang++‎ داخل بيئة لينكس في جلسة تفاعلية.
  - Python: python3 داخل بيئة لينكس في جلسة تفاعلية (الإدخال مفتوح لدالة input).
  - JavaScript: node داخل بيئة لينكس في جلسة تفاعلية.
  - HTML/CSS: معاينة حية في WebView.
- ملف run.stdin يُغذّى أولاً ثم تبقى الجلسة مفتوحة لكتابة المستخدم.
- زر الإيقاف (Stop) ينهي العملية الحية (مهم للحلقات اللانهائية).

3-5) بيئة لينكس المدمجة (EmbeddedLinuxBackend)
- بدلاً من مطالبة المستخدم بتثبيت تطبيق Termux خارجي، يُحمَّل
  نظام Termux المصغّر (bootstrap لمعمارية arm64) داخل التخزين الخاص
  للتطبيق (files/usr) عبر PrefixInstaller (تنزيل لمرة واحدة).
- التنفيذ عبر proot (محاكاة صلاحيات الجذر دون روت) مع ربط مساحة
  المشاريع المشتركة، ومخرجات البناء إلى مجلدات مؤقتة لتفادي البطء.
- الحزم (openjdk-17 و clang و python و nodejs) تُثبَّت عند الحاجة
  بأمر pkg من شاشة اللغات.
- الواجهة البرمجية ExecutionBackend تتيح: تنفيذ لقطة (capture) للأوامر
  القصيرة مثل javac و pkg، وجلسات تفاعلية مفتوحة الإدخال للبرامج.

3-6) الطرفية (Terminal)
- TerminalFragment يعرض جلسة bash المدمجة (أو toybox الاحتياطية)
  مع شريط مفاتيح إضافية (Ctrl/Esc/Tab/الأسهم) لأن لوحات هواتف أندرويد
  تفتقدها، ودعم كامل لإدخال المستخدم.

3-7) الجلسات والحفظ التلقائي
- SessionManager يحفظ لكل مشروع: التبويبات المفتوحة وترتيبها والملف
  النشط ومواضع المؤشر والمسودات غير المحفوظة في .larv/session.json.
- الحفظ التلقائي بعد ثانية من التوقف عن الكتابة، وحفظ إجباري متزامن
  قبل التشغيل وقبل تبديل المشاريع وقبل إغلاق التطبيق.
- عند تبديل المشاريع تُحفظ جلسة المشروع القديم أولاً ثم تُستعاد
  جلسة الجديد، والمشروع الجديد يفتح Main.java تلقائياً.

3-8) الإكمال والذكاء البرمجي (خفيف بالتصميم)
- ProjectIndexer يستخرج الرموز (أصناف/دوال/حقول) بالتعابير النمطية
  عند فتح الملفات، وMemberCatalog يوفّر إكمال الأعضاء بعد النقطة
  (مثل StringBuilder ← append) وإصلاح الاستيراد السريع.
- لا يوجد محلل لغوي كامل داخل التطبيق عمداً (ثقيل على الهواتف)؛
  الأخطاء الحية تأتي من مخرجات المترجمين وتُعرض في تبويب Problems.

----------------------------------------------------------------
4) كيف يعمل البرنامج خطوة بخطوة
----------------------------------------------------------------
أ) فتح التطبيق: يستعيد آخر مشروع (جلسة + تبويبات + مسودات) أو يعرض
   شاشة الترحيب، ويطبّق إعدادات المحرر المحفوظة.
ب) التحرير: الكتابة في Monaco ← دفع التعديلات للذاكرة ← حفظ تلقائي
   للقرص ← فهرسة للإكمال.
ج) الضغط على Run:
   1. دفع فوري لمحتوى المحرر (flush) ثم انتظار 250ms لوصول الجسر.
   2. حفظ كل الملفات المعدلة على القرص وتحديث الجلسة.
   3. التوجيه حسب اللغة (البند 3-4) ثم عرض المخرجات في الطرفية.
د) تشغيل Java تحديداً:
   javac (لينكس) ← class ← D8 (مكتبة داخل التطبيق) ← dex
   ← PathClassLoader على ART مع تمرير الوسائط وملف stdin.
هـ) لغات Terminal (بايثون/نود/C++): عملية لينكس حقيقية بإدخال
   مفتوح — يكتب المستخدم داخل نفس نافذة المخرجات.
و) الإعدادات: قسم Linux Environment يعرض الحالة (مثبت/غير محمّل/
   جارٍ التنزيل) مع زر تنزيل واحد، وحجم البيئة، وزر حذف لتوفير المساحة.
